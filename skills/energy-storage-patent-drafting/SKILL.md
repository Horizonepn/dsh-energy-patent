# 储能专利撰写

## 用途

把储能研发材料变成可递交的中国专利文件：先挖点、查新，再写交底书；需要时直接写权利要求书、说明书、摘要，并用 `patent_figure` 出黑白附图、`patent_docx` 出 Word。

## 输入与门禁

- 必需：发明人资料（文件夹/文档/代码/实验记录）路径。没有资料就不要凭空写；先向用户要路径。
- 先调 `patent_intake`，拿到 `caseId`、`digestPath`、领域分支和候选表述。后续所有事实以 digest 与原始文件为准，**不以聊天记忆当事实**。
- 用户未指定类型时默认**发明**；结构类改进可建议实用新型，但不要擅自改写类型。
- 材料缺申请人/发明人/联系人时只记入问题清单，不阻塞正文；缺技术事实（结构、参数、步骤）时问人，**不编**。

## 流程

### 第 1 步：摄入与挖点

1. 调 `patent_intake`（`path` 必填，可带 `focus`）。
2. 读 `digestPath`，按下列维度列 **3–5 个候选专利点**，每个写：技术背景、创新点、与现有技术的区别（初判）、可实施性、材料出处。
   - 材料/配方：组分、含量范围、粒径、改性/包覆、制备工艺窗口。
   - 结构/成组：电芯内部、顶盖/防爆阀、模组/PACK、冷板流道、箱体梁、连接排。
   - 控制/算法：采样量、判定条件、阈值、状态估计、均衡、热失控预警、调度策略。
   - 系统/集成：PCS/EMS/BMS 协同、簇级管理、构网控制、消防联动、光储充。
3. 用**删除测试**选主案：删掉某特征后方案还能否解决技术问题？不能 → 必要技术特征；能 → 优选特征。
4. 若两组点没有共同必要特征，建议拆案；不要为了凑一篇把两组发明点硬捏成假组合。

### 第 2 步：查新（轻量、可复核）

- 用 `web_search` 检索 3–4 组中英文关键词，优先 Google Patents / CNIPA 公布公告；必要时 `web_fetch` 打开具体公开页。
- 每组词覆盖：对象 + 手段 + 效果，例如「电池模组 液冷板 流道 温度均匀性」「储能 簇级 均衡 荷电状态」。
- 只把**真实打开过、能给出公开号**的文献写进对比；禁止编造公开号、标题或“检索不到所以全球首创”。
- 钉一篇最接近的 D1，写一句选定理由；做 3–5 行逐特征表（D1 是否公开 / 本案怎么做）。找不到 D1 就如实写「本次检索未钉住最接近现有技术」，把区别对材料中的常规做法写，创造性表述降级。
- 查新记录写入 `outputs/patent-workbench/cases/<caseId>/drafts/查新与区别定位_<时间戳>.md`。

### 第 3 步：写交底书

按下列章节写 Markdown，落盘到案件 `drafts/`，文件名 `交底书_<案件名>_<YYYYMMDD-HHmmss>.md`：

1. 注意事项（可选，简短）
2. 一、相关技术背景与最接近现有技术（1.1 现有技术；1.2 缺点）
3. 二、要解决的技术问题（只写“要达到什么”，**不得出现本案手段词**）
4. 三、技术方案详细阐述
   - 3.1 场景与术语（执行主体、对象如何进入系统、高频词定义）
   - 3.2 系统框图（用 `patent_figure` kind=block 出图，正文引用图号）
   - 3.3 模块/部件功能（一项一段，写作用与关联，不写空泛输入输出）
   - 3.4 流程/控制步骤（步骤一…步骤N，与独权同序同义）
   - 3.4.1 符号与公式（有公式才写；符号表、量纲、取值范围齐全）
   - 3.5 关键参数表（符号列与 3.4.1 一致）
5. 四、相对现有技术的优点（每条写完整效果句，把构造写进句子）
6. 五、技术关键点与欲保护点（5.1 必要技术特征；5.2 优选特征；每条复述全文，不只写编号）
7. 六、实施例（主路径 + 一条分支；参数、实验条件、测试方法可追溯）

写完后自检：技术问题里有没有手段词？效果句有没有对应构造？参数有没有材料出处？没有就改，不要留“待确认”进正文。

### 第 4 步：写申请文件

按顺序，不要跳步：

1. **权利要求书**（`权利要求书.md`）
   - 先独权 1，再按从属树写从属；独权不引用其他权项，从属只引用在先权项。
   - 方法独权用「包括以下步骤：步骤一，…；步骤二，…」。步骤名与流程图框内文字**逐字同义**。
   - 系统独权只写模块名称及连接/功能关系；不写件号、不写（10）（20）。
   - 公式与参数表放说明书；权要只保留文字限定的计算关系。
   - 每项写「其特征在于」；「所述X」必须在本项或所引权项中先出现。
   - 写完立即调 `patent_claim_check`，有 error 先改再继续。
2. **附图**：按权要语言决定图型，调 `patent_figure`：
   - 方法独权 → `flow`，步骤数 = 独权步骤数；分支/回环放从属和实施例，不进主流程图。
   - 系统/装置独权 → `block`，每个独权模块一个框；虚线分组写层级名。
   - 有实验数据 → `chart`（黑白柱/线图）。
   - 图号、图题不画进图片；图片由 `patent_figure` 直接写入案件 `figures/`。
3. **说明书**（`说明书.md`）五部分：
   - 技术领域：一句。
   - 背景技术：点名 1 件最接近对比写透（公开号 + 公开了什么 + 缺什么），不要检索列表/URL/“经检索”。
   - 发明内容：问题 → 独立方案（与独权同序）→ 从属要点「进一步」→ 有益效果单独成段。
   - 附图说明：图1为…示意图；图2为…示意图。
   - 具体实施方式：结合附图把主方案按步骤走通；实施例写参数、测试方法、数值例；材料没有的硬件细节不编。
4. **说明书摘要**（`说明书摘要.md`）：技术领域一句 + 现有不足一句 + 手段 + 效果一句，**不超过 300 字**，无宣传语，摘要附图默认主流程图。
5. 调 `patent_docx`（kind=application，传 `dir` 指向含三份 md 与 `figures/` 的目录）出 Word；同时写 `问题清单.md`（缺材料、待确认、假设），不混入正式文件。
6. 调 `patent_case` 更新：`status=filed`（或 `review`）、`eventType=draft`、`eventNote` 写清交付路径。

## 储能领域撰写要点

| 方向 | 必要技术特征抓手 | 常见审查风险 |
| --- | --- | --- |
| 材料/配方 | 组分 + 含量范围 + 粒径/形貌 + 制备步骤 + 测试条件 | 参数范围无实施例支持（A26.4）；效果数据不可比 |
| 电芯/结构 | 部件 + 连接/位置/配合 + 尺寸关系 + 装配顺序 | 纯尺寸优化缺技术效果；附图件号不一致 |
| 热管理/安全 | 流道/冷板/隔热/泄压 + 触发条件 + 联动动作 | 效果断言无实验；热失控机理写错 |
| BMS/控制 | 采样量 + 判定条件 + 阈值 + 控制动作 + 闭环 | 纯算法/商业规则客体（A2.2）；阈值无依据 |
| PCS/EMS | 拓扑 + 控制量 + 约束 + 调度目标 | 数学优化无技术手段；组合对比文件 |
| 系统集成 | 子系统 + 接口 + 协同逻辑 + 运行模式 | 模块罗列缺连接关系；上位概念过宽 |

- **分类号提示（须核验）**：H01M（电池/电芯/成组）、H01M10/48（BMS）、H01M10/613-655（热管理）、H01M50（壳体/成组）、H02J3/28-38（储能并网/调度）、H02J7（充放电）、H01G11（超级电容）、H01M8/18（液流）、F28D20（储热）、C25B（电解水）、G01R31/36（电池测试）。
- **术语统一**：电芯 / 模组 / 电池包 / 电池簇 / 储能系统；SOC / SOH / SOP；热失控 / 热扩散；液冷板 / 冷板；储能变流器（PCS）/ 能量管理系统（EMS）。全文同词，不要一会儿“电池组”一会儿“电池包”。
- **数值**：所有参数给范围 + 至少一个实施例值 + 测试方法；材料没有的数值不编，写“本实施例中可取…”并列入问题清单。
- **避免**：空喊“提高效率/延长寿命/增强安全”；只写目的不写手段；把商业收益、电价套利写成技术效果。

## 附图规范

- 纯黑线条、白底、无灰度/阴影/颜色；300dpi；按内容裁切，不留 A4 空白。
- 流程图：框内写「步骤一，…」，与独权步骤同序同义；不加 S1/201；不拉引出线。
- 框图：框内写模块名；虚线分组写层级；不标件号、不拉引出线。
- 图号与图题写在说明书「附图说明」和插图下方，**不要画进图片**。
- 结构剖视/爆炸/多状态图无法由文字自动生成：让用户提供 CAD/线稿/照片，`patent_docx` 可嵌入；不要凭空画内部结构。

## 交付

回复中给出：
- 交底书路径、申请文件目录、Word 路径、附图路径。
- 权利要求项数与 `patent_claim_check` 结果。
- 问题清单摘要（缺什么、哪些是假设）。
- 一句边界：本稿为内部草稿，须发明人确认技术事实、代理人复核后递交。

## 护栏

- 不编造技术事实、实验数据、对比文件、公开号；不把公司名/产品名/真实客户数据写进公开文件。
- 不承诺授权、不评价“创新性强”；不替代代理师签字。
- 不在未读材料的情况下写申请文件；不从聊天记录补技术细节。
- 已有产出上改稿另存新时间戳目录，不覆盖上一版。
