# 审查答复与邮箱办理

## 用途

把审查意见通知书或审查员邮件变成可执行的三件事：**提取意见 → 定策略 → 出意见陈述与回信**；同时把案件状态、轮次和期限写回案卷。

## 输入

- 通知书 PDF/DOCX，或邮箱中的审查员/代理机构来信（用 `patent_mail` 读取）。
- 本申请文件（权利要求书、说明书）路径；有则一并读。
- 案件号（`patent_case` 中已有）；没有就先建案或关联。

## 流程

### 第 1 步：拿到并提取通知书

1. 文件在本地：调 `patent_oa_extract`，传 `path` + `caseId`。
2. 在邮箱里：先 `patent_mail`（action=status）确认配置；再 `inbox`（query 可填申请号、发明名称、审查员、代理机构）→ `read`（saveAttachments=true）→ 把附件路径交给 `patent_oa_extract`。
3. 读返回的 `notice.md` 与 `notice.json`。**逐项核对**：申请号、发文日、审查员、通知书类型、对比文件、法条、逐条意见、答复期限。`confidence` 低或 `reviewFlags` 非空时，打开原文核对，不要直接照抄。
4. 期限以通知书指定日期为准；工具算的是「发文日 + 15 日推定送达 + 4/2 个月」的估算。把确定日期写回 `patent_case`（`oaReceivedDate` / `oaResponseDue` / `oaRound`）。

### 第 2 步：逐条定策略

对每一条缺陷，比较 2–3 条短路径，不写全文：

| 路径 | 一句话 | 主要风险 |
| --- | --- | --- |
| 仅意见陈述 | 争辩对比文件未公开区别特征，或结合无启示 | 审查员坚持时多一轮 |
| 修改权利要求 | 把从属特征上提/限缩独权 | 保护范围缩小；修改须有说明书支持 |
| 修改说明书 | 澄清、补入实施例中已有内容 | 不得超范围（A33） |
| 补正形式 | 引用关系、编号、摘要、附图 | 形式问题反复 |

评分只用两个相对维度：**稳妥分**（本条被克服的把握）与**保范围分**（保护范围保留程度），都是 0–100 的相对分，**不是授权率**。

选定规则（按申请人利益，禁止裸选最高分）：
1. 纯形式/手续问题 → 主策略「补正形式」，不做创造性比较。
2. 清楚性/支持问题且仅争无法消除 → 可直接修改权利要求。
3. 新颖性/创造性等实体缺陷 → 默认「仅意见陈述」；只有同时满足才改「修改权利要求」：只争与缩权的稳妥分差 ≥15，且通知书表明仅争很难成立。
4. 多条缺陷分别定策略，再拼进同一份意见陈述（第 1 条可只争，第 2 条可改权要）。
5. 修改每一处都要指向说明书支持位置；找不到就标「待发明人指认段落」，不要编。

### 第 3 步：写意见陈述

落盘到 `outputs/patent-workbench/cases/<caseId>/drafts/`，文件名 `意见陈述_<YYYYMMDD-HHmmss>.md`。结构：

1. 著录项目：申请号、发明名称、申请人、通知书名称与发文日。
2. 答复说明：收到通知书、逐条答复如下。
3. 逐条答复：引用通知书条目编号 → 审查员观点摘要 → 申请人意见（对比文件公开内容、区别特征、技术效果、为何非显而易见）→ 修改说明（如有）。
4. 修改说明：修改前/修改后、说明书支持段落、未超范围说明。
5. 结论与请求：请审查员继续审查/授予专利权。
6. 附件清单：权利要求替换页、修改对照页、实验数据（如有）。

写作要求：
- 只写审查员需要看的内容；不写内部策略、相对分、案例编号、检索过程。
- 对比文件用公开号；不要贬低审查员，不做人身评价。
- 每条答复落到**技术特征 + 技术效果**，不要空喊“具有创造性”。
- 修改不得超出原说明书和权利要求书记载的范围；新增实验数据只能用于证明原申请已公开的效果，不能补新技术方案。

### 第 4 步：出 Word

调 `patent_docx`（kind=opinion，documents 里给 `name=意见陈述`、markdown、`indentFirstLine=true`），输出到案件 drafts。内部复核后再递交。

### 第 5 步：回复邮件

1. `patent_mail`（action=draft，uid=原邮件 UID，body=回信正文，caseId=案件号）生成 `.eml`。
2. 回信只写：收到、已按期限处理、附件名称、需对方确认的事项；不要把意见陈述全文贴进邮件。
3. 把草稿路径、收件人、主题给用户看；**用户明确确认后**才 `send`（confirm="SEND"）。
4. 发送后在 `patent_case` 记事件 `mail_sent`，并把 `oaResponseDue` 与 `responseSentAt` 写进 notes/event。

### 第 6 步：收口案卷

- 答复提交后：`patent_case` update `status=oa`，事件 `response_sent`，备注答复稿路径与提交日。
- 授权后：`status=granted`，记录授权公告号/授权日；提示年费期限。
- 驳回：`status=rejected`，记录复审期限（收到驳回决定之日起 3 个月），提示是否复审。

## 储能 OA 高频问题

| 缺陷 | 常见审查意见 | 答复抓手 |
| --- | --- | --- |
| 创造性（A22.3） | D1+D2 结合，区别特征是常规选择 | 指出 D2 无结合启示、区别特征带来预料不到的效果、对比文件技术领域/作用不同 |
| 清楚/支持（A26.4） | 参数范围过宽、功能限定无实施例 | 用说明书实施例缩范围；补入已有实验数据说明趋势；删除无支持的上位表述 |
| 充分公开（A26.3） | 制备/测试条件不明、无法实现 | 用原说明书已记载的工艺窗口、测试标准答复；不得新增技术方案 |
| 客体（A2.2） | 纯算法/调度/商业规则 | 强调与电池硬件、采样/控制动作的结合，写清技术问题与技术效果 |
| 必要技术特征（R20.2） | 独权缺少实现发明目的的必要特征 | 从说明书和从属权项上提；说明该特征为何必要 |
| 修改超范围（A33） | 修改内容原申请未记载 | 逐字指向原说明书段落/附图；删除无依据修改 |

储能领域特别注意：
- 电池安全类：热失控触发条件、泄压/消防联动要有实验或标准依据，不要把“绝对安全”写进效果。
- BMS/EMS 类：算法权要要绑定采样对象、执行机构和技术效果；纯收益优化容易被认定为商业规则。
- 材料类：参数范围与实施例数量匹配；比较例的测试条件要一致。
- 系统集成类：模块之间的连接/通信关系要写清，避免“模块罗列”。

## 邮件写作模板

主题：`答复：<申请号> <发明名称> 第一次审查意见通知书`

正文：
```
<审查员/代理师> 您好：

附件为 <申请号>「<发明名称>」针对 <通知书名称>（发文日 <日期>）的意见陈述及修改替换页，请查收。

本次答复要点：
1. 针对第 1 条（<法条/缺陷>）：<一句策略与结论>；
2. 针对第 2 条：<一句>。

如需补充实验数据或修改替换页，请告知。谢谢！

<姓名>
<单位/部门>
<电话>
```

## 邮箱配置

`patent_mail` 读取工作区根目录的 `patent-mail.config.json`，或 `~/.dsh/patent-mail.config.json`（也可用 `configPath` 指定）。最小配置：

```json
{
  "imap": {"host": "imap.example.com", "port": 993, "secure": true, "user": "ip@example.com", "passwordEnv": "PATENT_MAIL_PASSWORD", "mailbox": "INBOX"},
  "smtp": {"host": "smtp.example.com", "port": 465, "secure": true, "user": "ip@example.com", "passwordEnv": "PATENT_MAIL_PASSWORD"},
  "fromName": "知识产权部",
  "signature": "知识产权部\n某储能科技有限公司"
}
```

- 密码写 `password` 或 `passwordEnv`（推荐环境变量/授权码）；不要使用主邮箱密码，不要把配置提交到仓库。
- 先 `action=status` 确认 `passwordSet`；再 `inbox`/`read`。读取使用 BODY.PEEK，不会把邮件标记为已读。
- 只支持密码认证的 IMAP/SMTP；企业邮箱若强制 OAuth2，请用应用专用密码或改用客户端转发。

## 护栏

- 不编造对比文件、公开号、实验数据、审查员姓名；不承诺授权。
- 不代替代理师签字；意见陈述与邮件都须人工复核后递交。
- 未经用户明确确认，不发送任何邮件；不批量标记已读、不删除邮件。
- 期限提醒是估算，必须回到通知书指定日期；逾期风险由人工确认。
