# 专利案卷与组合维护

## 用途

用 `patent_case` 维护一份可追溯的专利台账：每件案子的状态、申请号、审查员、审查轮次、期限和事件。目标不是“记流水账”，而是让下一件该做的事（补材料、答复、缴费、布局）自动浮出来。

## 数据位置

```
<工作区>/outputs/patent-workbench/
  docket.json                 # 台账主数据
  TRACKER.md                  # 自动生成的台账
  cases/<caseId>/
    materials/                # 资料摘要
    drafts/                   # 交底书、申请文件、意见陈述
    figures/                  # 黑白附图
    oa/                       # 通知书提取结果
    mail/                     # 邮件草稿与附件
```

`case.json` 不是独立文件；案件对象保存在 `docket.json` 的 `cases` 数组里，每个案件目录用于放产出。

## 状态机

`drafting`（撰写中）→ `review`（内部复核）→ `filed`（已申请）→ `oa`（审查中）→ `granted`（已授权）/ `rejected`（已驳回）/ `abandoned`（已放弃）；`archived` 为归档。

- 每完成一次交付/递交/收文/答复，都要 `patent_case` action=update 或 event，写清 `eventType` 与 `eventNote`。
- 不要用聊天记忆代替台账；下次进入先 `patent_case` action=list 或 get。

## 日常流程

### 1. 盘点

1. `patent_case` action=list（可按 status 过滤）看全量。
2. `patent_case` action=deadlines 看 90 天内与已逾期事项。
3. 对每件 `urgent` / `overdue`：确认是答复期限、年费还是优先权期限，给出下一步动作与负责人。

### 2. 更新

- 新建：action=create，至少给 `title`、`patentType`；能拿到申请人/发明人一并填。
- 收到申请号/受理通知书：update `applicationNo`、`filingDate`、`status=filed`。
- 收到审查意见：优先走 `energy-storage-patent-prosecution`（会自动把案件转 `oa` 并记录轮次），再补 `examiner`、`oaResponseDue`。
- 授权：update `status=granted`，在 event 里记授权公告号与授权日。
- 驳回/放弃：update 对应状态，event 写原因与复审/恢复期限。

### 3. 出表

- `patent_case` action=tracker 重新生成 `TRACKER.md`。
- 月度盘点按下面模板输出，不要只贴 JSON。

## 期限规则（工具内估算）

| 事项 | 规则 | 说明 |
| --- | --- | --- |
| 审查意见答复 | 发文日 + 15 日推定送达 + 4 个月（发明）/ 2 个月（实用新型、外观） | 以通知书指定期限为准；可申请延期的情况单独确认 |
| 年费 | 申请日周年 | 缴费窗口、滞纳金、权利恢复以国知局缴费通知为准 |
| 优先权 | 申请日起 12 个月 | 仅在有申请日且尚未取得申请号时提示 |
| 复审 | 收到驳回决定之日起 3 个月 | 需人工确认收到日 |

所有日期都是**提醒**，不是法律期限管理；逾期前必须人工复核。

## 组合布局（1+N）

核心案授权或首篇定稿后，才考虑保护型布局：

1. 拆解核心必要特征，列出可替代的实施方式。
2. 设计外围案：材料替代、结构变型、控制策略、系统集成、应用场景。
3. 做规避设计矩阵：每件外围案与核心案的区别特征、独权落点、是否共享必要特征。
4. 先写立项说明（保护目标、预算、申请国别、时间窗），用户确认后再分件撰写。
5. 不要把同一方案换几个词重复申请；不要为了数量拆出没有独立价值的案子。

## 护栏

- 不虚报状态、不编申请号/授权号；拿不到的信息留空并列入待补。
- 期限只做提醒，不替代代理机构/企业 IP 管理流程。
- 年费、复审、恢复权利等涉费/涉权事项必须人工确认后再操作。
- 组合布局建议是技术-商业判断，不构成法律意见。
